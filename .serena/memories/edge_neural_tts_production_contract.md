# Edge Neural TTS Protocol & Production Stream Architecture (Updated)

## 1. Root Cause Diagnosed (October 2026 Edge TTS DRM v2 Transition)
1. **Microsoft Bing Edge-TTS Handshake 403**: Microsoft rolled out DRM v2 on `speech.platform.bing.com`, requiring `Sec-MS-GEC-Version: 2-143.0.3650.75` and a new CS64 + SHA-256 compound token (`generate_sec_ms_gec_v2`). The older v1 handshake returned HTTP 403 Forbidden on the initial WebSocket dial, causing a 6-second timeout before falling back.
2. **Local edge-tts Version**: Machine was on `edge-tts 7.2.8` which still sent v1 tokens. Upgrading to `edge-tts 7.3.1` unlocked native DRM v2 generation and instant synthesis.
3. **Synthesis Pipeline Ordering in Go Backend (`service.go`)**: Swapped execution order to prioritize `synthesizeEdgePython` (which runs `edge_synth.py` with DRM v2 and returns word boundaries in <2s) ahead of the legacy WebSocket dial, eliminating the 6-second handshake freeze.
4. **Browser Autoplay & AudioContext Unlock**: In Chromium/Safari, clicking "Dictar clase" or "Oír ejemplo" triggered asynchronous fetches without priming the `AudioContext` during the user gesture stack. Integrated `MobileAudioUnlocker.unlock()` synchronously inside all click handlers (`handleToggleLecture`, `handleAskQuestion`, `handlePlaySample`).
5. **Fail-Safe Browser SpeechSynthesis Fallback**: In `SpeechSynthesisService.speak`, when direct HTMLAudioElement and Web Audio buffer both fail, it now seamlessly routes to `this.speakFallback(trimmed, options, playbackId)` instead of calling `onEnd()` silently, guaranteeing zero-silence delivery under all network conditions.
